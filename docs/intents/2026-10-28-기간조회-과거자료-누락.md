# Intent: 기간 지정 조회 시 과거(10/21 이전) 자료 누락 해소

## 1. 배경 및 문제
- 현재 문제: 기간 지정(2026-10-01 ~ 2026-10-28)으로 조회하면 10/21 이후만 나오고 그 이전 파일은 보이지 않는다.
- 원인 진단(확인함):
  - 화면 필터(`html.js` `inRange`/`getRange`)는 정상이다. 데이터 자체에 과거 자료가 없다.
  - 데이터 출처는 Windows 「최근 문서」 폴더(`%APPDATA%\Microsoft\Windows\Recent`)의 `.lnk`뿐이다(`cache.js:80`). 이 PC에는 바로가기 152개, 가장 오래된 것이 10/15이며 날짜별로 10/15 2건 · 10/19 1건 · 10/21 5건 · 10/22 24건 · 10/26 55건 · 10/27 33건 · 10/28 32건이다. Windows가 오래된 바로가기를 스스로 지운다.
  - 확장자 필터·일괄접근 제외(`BURST_MIN=8`)·중복 제거를 거쳐 화면에는 73개가 남는다.
  - 즉 10/21 이전은 "필터 오류"가 아니라 "수집된 적 없는 자료"다.
- 영향받는 업무/사용자: 파일 타임라인으로 "그때 무슨 파일을 열었더라"를 기간별로 되짚는 사용자.

## 2. 목표
- 달성하려는 결과: 앱이 실행될 때마다 최근 문서 기록을 로컬에 누적 저장하고, 기간 조회는 누적 기록 전체에서 필터링한다.
- 성공 기준:
  1. 앱을 여러 날에 걸쳐 실행한 뒤, Windows가 바로가기를 지워도 이전에 수집한 기록이 기간 조회에 나온다.
  2. 누적 기록이 없는 구간을 조회하면 "기록은 YYYY-MM-DD부터 있습니다" 안내가 보인다.
  3. 기존 탭(오늘·어제·이번 주·이번 달·전체)과 검색 결과가 기존과 동일하게 동작한다.
  4. 같은 파일을 반복 수집해도 중복 행이 생기지 않는다.

## 3. 범위
### 포함
- 앱 시작·새로고침 시 최근 문서 기록을 로컬 JSON 파일에 병합 저장(누적).
- `/api/recent`가 누적 기록(+ 이번 수집분)을 반환.
- 기간 조회 결과가 비어 있거나 시작일 이전을 포함할 때 데이터 시작일 안내 표시.
- 기존 제외 규칙(같은 1분 8건 이상 일괄 접근, `OKF_지식위키\sources`) 유지.
### 제외
- 파일 수정일 기준 PC 스캔(Windows 검색 색인 이용) — 사용자가 선택하지 않음.
- Windows가 이미 지운 기록의 복원(불가능).

### 추가 범위 (2026-10-28, 사용자 요청: 더 오래된 기록도 조회)
- 수집원 확장: Recent `.lnk`에 더해 `%APPDATA%\Microsoft\Office\Recent`(109건, 2025-01~)와 점프리스트 `Recent\AutomaticDestinations`(121개 파일, 2025-02~)의 DestList 항목(경로+마지막 접근 시각)을 읽는다. 점프리스트는 OLE(CFB) 형식이라 외부 패키지 없이 최소 파서를 직접 작성한다.
- 날짜 필터 로직 자체의 변경(정상 동작 확인됨).

## 4. 관련 시스템·데이터
| 구분 | 내용 |
|---|---|
| 대상 시스템 | FileTimeline2 (Node/Express 로컬 서버 + 단일 HTML UI, exe 패키징) |
| 입력 데이터 | Windows 최근 문서 `.lnk` (`cache.js`) |
| 출력/결과 | 누적 기록 JSON(신규), `/api/recent` 응답, 기간 조회 화면 |
| 연계 시스템 | 없음 |

## 5. 제약 조건
- 신규 외부 패키지 추가 없음(Node 표준 `fs`만 사용).
- exe로 패키징돼도 쓰기 가능한 위치여야 한다 — 저장 경로는 절대경로 하드코딩 금지(전역 `file-layout.md`).
- 기존 일괄접근·폴더 제외 규칙 유지.

## 6. 주요 프로세스
1. 앱 시작/새로고침 → 최근 문서 스캔(기존 로직).
2. 스캔 결과를 누적 기록과 병합(같은 `fullPath`는 가장 최근 `accessTime` 하나로 유지).
3. 병합본을 JSON으로 저장하고 UI에 전달.
4. UI는 기존 `inRange`로 필터링하고, 기간 시작일이 누적 기록 최초일보다 앞서면 안내 문구 표시.

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 데이터 없음(누적 기록 비어 있음) | 기존 빈 상태 화면 유지 + 시작일 안내 |
| 누적 파일 손상·읽기 실패 | 백업 후 새로 시작, 이번 스캔분은 유지(조용히 삼키지 않고 진단 정보에 기록) |
| 누적 파일 무한 증가 | 파일 수 한계 필요 여부는 미해결 질문 |
| 같은 파일을 다시 열면 | 마지막 접근 시각으로 갱신(과거 접근 이력은 1건만 유지) |
| 지금까지 못 모은 과거 | 복원 불가 — 안내 문구로 한계를 명시 |

## 8. 미해결 질문
- 누적 JSON 저장 위치: exe 옆 `data\history.json` vs 사용자 프로필 폴더(`%APPDATA%`). (계획 단계에서 `pkg` 설정 확인 후 제안)
- 같은 파일의 접근 이력을 1건만 둘지(최신만), 접근마다 모두 둘지. 기본안은 최신 1건.
- 누적 기록 보관 상한(예: 1년 또는 건수 상한) 필요 여부.
